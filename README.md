# Birthday Quest

이경의 생일(2026-10-24)이 시험기간과 겹쳤다. 본인 의견을 먼저 듣고 그걸 참고해 생일을
준비하려고 만든 선형 설문 웹앱이다.

**빌드 도구·패키지 매니저·프레임워크 없이 동작한다.** ES 모듈 + 정적 파일이 전부고,
외부 스크립트도 라이브러리도 쓰지 않는다. UI(양피지 책·달력·버튼·진행 표시)는 전부 CSS 로
그렸고, 파티클과 결과 이미지는 canvas, 배경음악은 오실레이터로 직접 만든다.

---

## 실행

정적 파일이라 아무 정적 서버로나 열면 된다. (`file://` 로는 ES 모듈이 막혀서 안 된다.)

```bash
python -m http.server 8098
# → http://localhost:8098/index.html
```

### 개발용 URL 파라미터

| 파라미터 | 하는 일 |
|---|---|
| `?screen=date` | 그 화면에서 바로 시작 (스크린샷·검증용) |
| `?screen=payoff&from=style` | 보상 화면은 어느 질문에서 왔는지도 받는다 |
| `&seed` | 답을 미리 채워 넣는다 (요약·완료 화면 확인용) |
| `?fresh` | 저장해둔 답을 지우고 처음부터 |

### `_probe.html` — 가로 넘침 진단

```bash
chrome --headless=new --dump-dom "http://localhost:8098/_probe.html?w=390&screen=date&seed"
```

앱을 `w` 픽셀짜리 iframe 안에 띄우고, 뷰포트보다 넓은 요소를 찾아 적어준다.
**iframe 을 쓰는 이유**: Chrome 헤드리스는 Windows 에서 창 너비를 ~490px 아래로 못 내려서
`--window-size=390` 을 줘도 실제 뷰포트가 390 이 되지 않는다. 그대로 캡처하면 레이아웃은
490px 로 잡힌 채 이미지만 390px 로 잘려서, 멀쩡한 화면이 깨진 것처럼 보인다.

## 질문 순서

생일 당일에 대한 의견을 **먼저** 듣고, 그 뒤에 제대로 축하할 날짜를 묻는다.

```
START → 인사 → 퀘스트 안내
  → ① 🎂 생일 당일 플레이 스타일   (SURVIVAL / BIRTHDAY / RANDOM)
  → ② 📅 제대로 축하할 날짜         (선호 순위 매기기)
  → ③ 🍴 먹고 싶은 음식            (무엇을 + 어떻게, 둘 다 순위)
  → ④ 🎁 갖고 싶은 것
  → 📜 결과 확인 → ❤️ 완료
```

네 질문은 **서로 독립**이다. `birthdayStyle` 은 의견 수렴일 뿐이라, SURVIVAL 을 골랐다고
날짜 선택지가 좁아지거나 후보 날짜가 자동으로 정해지지 않는다.

질문을 하나 마칠 때마다 `src/screens/payoff.js` 한 군데로 모여서 같은 모양으로 끝난다
(리액션 대사 → XP → 다음 질문 예고). 이 화면만 고치면 네 질문의 보상 연출이 한꺼번에 바뀐다.

요약 화면에서 한 줄을 눌러 고치러 가면 `ret` 이 따라붙고, 그 화면은 보상을 건너뛰고
**곧장 요약으로 돌아온다.** 한 줄 고치자고 끝까지 다시 걷지 않아도 된다.

## 데이터

```js
birthdayPlan = {
  birthdayStyle: '',      // 'survival' | 'birthday' | 'random'
  datePreferences: [],    // [{ date: '2026-10-13', rank: 1 }, ...]
  dateNote: '',
  foodPreferences: [],    // [{ key: 'seafood', rank: 1 }, ...]   무엇을
  foodAny: false,         // 알아서 잘 해봐라 (순위를 매기지 않음)
  customFood: '',         // foodPreferences 에 'other' 가 있을 때
  mealPreferences: [],    // [{ key: 'bbq', rank: 1 }, ...]       어떻게
  mealAny: false,
  customMeal: '',         // mealPreferences 에 'other' 가 있을 때
  giftType: '',           // 'have' | 'any'
  giftNote: '',
  lastWord: '',           // 요약 맨 아래에 자유롭게 적는 한마디
}
```

음식 코너는 **"무엇을" 과 "어떻게" 를 따로 묻는다.** 둘 다 선호 순위라서, 순위 로직
(`src/ui/rank.js` 의 `toggle`)을 달력과 공유한다. 한쪽에서 `알아서` 를 골라도 다른 쪽은
그대로다 — 두 질문은 서로 독립이다. 양쪽 다 `기타` 를 고르면 적어야 넘어갈 수 있다.

### 저장과 되살리기를 갈라놨다

| | 하는 일 |
|---|---|
| `sessionStorage` | **되살리기 전담.** 새로고침은 버티고, 창을 닫으면 사라진다 |
| `localStorage` | 보관용 사본. 쓰기만 하고 **다시 읽지 않는다** |

되살리기까지 `localStorage` 로 하면, 만들면서 눌러본 답이 다음에 들어온 사람 화면에
"미리 골라진" 채로 나타난다. 읽는 쪽만 세션으로 끊어서 **창을 새로 열면 늘 빈 상태**다.

서버도 계정도 쓰지 않는다. 답이 돌아오는 길은 완료 화면에서 본인이 보내주는 **그림 한 장**뿐이다.
링크를 받은 사람이 로그인 없이 바로 열 수 있는 쪽이 낫다고 봤다.

### 결과 이미지 (`src/ui/card.js`)

요약 화면을 그대로 캡처하지 않는다. 완료 화면에 오면 그 화면은 이미 문서에서 사라졌고,
DOM 캡처는 글꼴이 늦게 붙으면 글자가 깨진다. **같은 내용을 canvas 에 다시 그린다.**

```
[📤 결과 보내기]  navigator.share({files}) → 글 복사 → 직접 복사용 textarea
[🖼️ 이미지로 저장] claude.use('downloads') → 안 되면 "캡처해서 보내다오"
```

아티팩트는 샌드박스 안에서 돌아가므로 `<a download>` 가 그냥 막힌다. 파일을 건네주는
공식 통로는 `downloads` 기능뿐이다.

## 눈여겨볼 구현 결정

### XP 는 진행 표시와 같은 눈금을 쓴다

점 하나 = 막대 한 칸 = `XP_STEP`. `STEPS` 배열 하나가 배너의 점 개수와 막대 칸 수를 함께
정하므로, 둘이 어긋날 수가 없다. 이미 답한 질문을 고치러 와서 다시 마치면 `+20 XP` 대신
`✅ 이미 받은 보상이로다~` 가 뜬다 — 합계가 안 늘어나는 이유를 화면이 설명해야 한다.

### 배경: 그림 두 장 + 그 위의 반짝임

바탕은 `assets/bg/night.jpg`(평소)와 `festa.jpg`(마지막 퀘스트 이후)이고, 그 위에 깜빡이는
별과 십자반짝임만 CSS 로 얹는다. 그림이 이미 그려둔 것(달·구름·섬·물결·등불)은
`quest.css` 에서 꺼둔다. 그림을 빼고 싶으면 `.photo` 두 줄만 지우면 **CSS 로만 그린 배경이
그대로 되살아난다** — 달·구름·파도·달빛기둥 코드가 전부 남아 있다.

전환 시점은 답변 상태가 아니라 **화면**이 정한다(`festa` 플래그). 답변 상태로 정하면
이어서 들어온 사람은 인사 화면부터 폭죽이 터진다.

### 누를 수 없는 NO 버튼

지켜야 할 것이 두 가지다. **화면 밖으로 나가지 않을 것**, **스크롤을 만들지 않을 것.**

```
index.html
└─ #roam              position:fixed 레이어 — 문서 높이에 영향을 주지 않는다
   └─ .roam-btn       좌표를 [10, innerWidth-너비-10] 안으로 묶는다

본문 안에 두면 안 되는 이유: .screen 의 등장 애니메이션이 transform 을 쓰는데,
transform 이 걸린 조상 안에서는 position:fixed 가 그 조상 기준으로 갇혀버린다.
```

- **YES 보다 위로는 달아나지 않는다.** 화면 꼭대기까지 올라가면 폰에서 손이 닿지 않고,
  말풍선과 YES 를 가려서 정작 눌러야 할 것이 눌리지 않는다.
- 놀리는 문구는 위쪽 말풍선이 아니라 **도망친 버튼 옆**에 뜬다. 버튼 `left/top` 에 트랜지션이
  걸려 있어 옮긴 직후에 좌표를 재면 떠나기 전 자리가 나오므로, 목적지를 직접 넘긴다.
- 글꼴·그림·영상이 늦게 도착해 본문 높이가 바뀌면 `ResizeObserver` 로 **다시 앉는다.**
  안 그러면 처음 앉은 자리에 남아 YES 위에 겹친다.
- 터치에서는 `pointerenter` 와 `pointerdown` 이 같이 들어오므로 180ms 안의 중복은 한 번으로 친다.
- **NO 는 어떤 값으로도 저장되지 않는다.** YES 를 눌러야만 다음으로 간다.

### 그 밖에

- **문구와 로직을 갈라놨다.** 화면 모듈은 `content.ko.js` 의 데이터를 읽어 그리기만 한다.
- **`h()` 는 문자열 자식을 `textContent` 로만 넣는다.** HTML 주입이 구조적으로 불가능하다.
- **순위는 `rank.js` 의 `toggle()` 하나가 전부다.** 뺀 뒤 항상 1..n 으로 다시 번호를 매기므로
  순위에 구멍이 생길 수 없다.
- **요약·결과 그림·보내는 글은 `summaryRows()` 한 군데서 나온다.** 항목을 고치면 셋이 같이 따라온다.
- **입력칸은 400ms 쉬었다 저장하고, 화면을 떠나기 전에 값을 확정한다.** 적자마자 버튼을
  누르면 완료 화면이 그 즉시 결과 그림을 그려서 마지막 글자가 빠진다.
- **이모지 폰트는 폰트 목록 맨 뒤에 둔다.** 앞에 두면 Apple Color Emoji 가 숫자 글리프를
  가져가서 iOS 에서 자간이 벌어진다.
- **별 깜빡임은 `opacity` 가 아니라 `filter:opacity()` 로 준다.** 별마다 인라인 `opacity`
  가 달라서, 같은 속성을 키프레임에서 건드리면 그 차이가 날아간다.
- **음악은 `muted` 를 속성이 아니라 프로퍼티로 꺼야 한다.** 속성만 달면 크롬이 자동재생을 막는다.
  소리는 사람이 무언가 누른 뒤에만 날 수 있어서, START 버튼 처리 안에서 시작한다.
- **캐릭터 그림은 넣지 않는다.** 직접 그린 픽셀 캐릭터를 한 번 넣어봤다가 뺐다 — 주변의
  양피지·달력·버튼이 전부 정교한 블록 UI인데 캐릭터만 손으로 찍은 티가 나서, 있을 때가
  없을 때보다 완성도가 낮아 보였다.
